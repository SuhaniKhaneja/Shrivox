# Shrivox — free portfolio deployment (₹0)

This guide describes a hobby/placement demo, not production hosting. Free services can sleep, restart, lose ephemeral state, run out of quota, or become unavailable under provider policy changes. Do not use real customer data.

## Architecture

- **Render Free Web Service:** FastAPI + Docker, public HTTPS and WebSockets.
- **Neon Free:** PostgreSQL with the `vector` extension and tenant data.
- **Render Free Key Value:** Redis-compatible ephemeral memory for session history and rate-limit counters.
- **Google AI Studio:** existing Gemini API key for generation and embeddings, subject to free-tier quotas and current Google terms.

`render.yaml` creates only a free web service and a free Key Value instance. It does not create a database, add a paid service, configure a custom domain, or run an uptime pinger. Create a Neon free project separately and choose Singapore if it is available. Choose the same region in Render for the web and Key Value services.

## Free-tier limitations

- Render Free web services sleep after 15 minutes without inbound traffic and can take about a minute to wake. They have 512 MB RAM, 750 included instance-hours per workspace per month, and ephemeral filesystems.
- Render Free Key Value has 25 MB RAM, no persistence, and a 50-connection limit. Its contents are lost on restart. Shrivox uses it only for temporary session history and rate-limit state; PostgreSQL remains the durable record.
- Neon Free currently lists 1 GB of storage and 100 CU-hours per project per month. Compute can suspend when idle and resume on the next connection. Check the current plan limits in the Neon dashboard before creating the project.
- Gemini free-tier quotas and model availability vary. A `429` is a quota/rate-limit response, not a hosting failure. No quota bypass or paid fallback is configured.
- Free plans and eligibility can change. This deployment intentionally has no keep-awake pinger; the cold start is accepted rather than consuming workspace hours or relying on an unverified sleep-prevention workaround.

## 1. Create Neon database

1. Create a Neon account and a free project. Select Singapore if offered and choose a PostgreSQL version compatible with the current Neon free plan.
2. Open the SQL editor and run:

   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   SELECT extversion FROM pg_extension WHERE extname = 'vector';
   ```

3. Copy the **direct** connection URI from Neon. Do not use the pooled `-pooler` hostname for this app's asyncpg connection unless you separately validate prepared-statement behavior. The app uses a small local SQLAlchemy pool instead.
4. Use a SQLAlchemy asyncpg URL. Change only the scheme from `postgresql://` to `postgresql+asyncpg://`, preserve the percent-encoded username/password/host/database, and keep `sslmode=require` if Neon includes it. Do not paste the URI into Git, screenshots, issues, or chat.

The connection helper converts `sslmode=require` into asyncpg's `ssl="require"`, removes the libpq-only `channel_binding` query option, and also supports `DATABASE_REQUIRE_TLS=true`.

## 2. Create Render services

1. Connect the GitHub repository to Render.
2. After the readiness changes are reviewed and merged, create a new Blueprint from the repository's `render.yaml` on `main`.
3. Confirm that both resources show the **Free** plan: `shrivox-api` (web) and `shrivox-redis` (Key Value). Do not select an upgrade, paid instance, or add-on.
4. Set the prompted `POSTGRES_DSN` to the Neon asyncpg URL and `GOOGLE_API_KEY` to the existing AI Studio key. `JWT_SECRET` is generated by Render.
5. Confirm the web service and Key Value are both in Singapore. The Key Value allowlist is empty, which permits internal connections only. The web service reads its internal Redis connection URL from the Blueprint reference.
6. Deploy the web service after setting the required values. Render supplies `PORT`; the Docker command uses it and retains port 8000 for local Compose.

## 3. Initialise Neon from your laptop

Render Free does not provide service shell access or one-off/pre-deploy commands. Run these commands from a trusted machine in the repository root, after setting the deployment variables. The seed script requires a dedicated synthetic demo email and a unique password. Do not reuse a personal or important account password.

PowerShell example:

```powershell
$env:POSTGRES_DSN = Read-Host "Paste Neon asyncpg connection URL"
$env:DATABASE_REQUIRE_TLS = "true"
$env:DEMO_EMAIL = Read-Host "Dedicated demo email"
$secure = Read-Host "Unique demo password (12-72 UTF-8 bytes)" -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
try { $env:DEMO_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr) }

python scripts/init_db.py
python scripts/seed_demo_business.py

Remove-Item Env:\DEMO_PASSWORD
Remove-Item Env:\POSTGRES_DSN
Remove-Item Env:\DATABASE_REQUIRE_TLS
Remove-Item Env:\DEMO_EMAIL
```

`GOOGLE_API_KEY` and `JWT_SECRET` must also be available to the local process (for example through the local `.env` file). The seed script embeds the sample KB using Gemini, so this consumes the Google free-tier quota. The seed operation is idempotent: rerunning it with the same email/business and a complete KB skips duplicate data. If a partial KB seed was interrupted, the next run removes that incomplete demo document and rebuilds it. The script does not print the password or reset an existing account's password.

**Important:** use a separate, empty Neon database/project for this demo. `init_db.py` creates schema objects and the seed script writes a synthetic demo tenant. Never point it at a personal or other application's database.

## 4. Configure the public demo

The Blueprint sets:

- `ENVIRONMENT=production`
- `REGISTRATION_ENABLED=false`
- `RATE_LIMIT_ENABLED=true`
- `METRICS_ENABLED=false`
- `DATABASE_REQUIRE_TLS=true`
- a one-connection SQLAlchemy pool

The public `/metrics` route returns 404 when disabled. `/health` remains a lightweight process health endpoint; it does not expose database details. `/docs` is the FastAPI Swagger UI. WebSocket clients connect to the documented `/api/v1/voice/stream/{session_id}` path with the short-lived chat ticket from `/api/v1/auth/chat-ticket`.

The browser chat page is a separate Stage B task; this stage does not add a fake or simulated chat UI. For now, use the existing `scripts/test_chat.py` from a trusted machine with the demo credentials.

## 5. Smoke-test checklist

1. Open `https://<service>.onrender.com/health`; expect `{"status":"ok"}` after any cold start.
2. Open `/docs`; confirm the OpenAPI endpoints render.
3. Log in as the seeded synthetic demo user; verify registration is disabled.
4. Mint a short-lived chat ticket and connect to the WebSocket.
5. Send a harmless English and Hinglish question; verify responses are backed by the seeded tenant KB.
6. Disconnect and reconnect; note that Render Key Value data can disappear on restart, so conversation durability must be checked in PostgreSQL.
7. Confirm `/metrics` returns 404.
8. Do not use other tenants' real data or publish the demo password in the repository.

## Troubleshooting

- **Service boot fails:** check `GOOGLE_API_KEY`, `POSTGRES_DSN`, `JWT_SECRET`, TLS and Render logs. The app requires PostgreSQL at startup because it creates the vector extension and schedules HNSW setup.
- **Missing tables:** run `python scripts/init_db.py` from the laptop against the same Neon database configured in Render.
- **Vector extension unavailable:** run the extension query in the Neon SQL editor and inspect `extversion`. If pgvector is below 0.8, the app must use the exact-search fallback; do not claim HNSW iterative scan is active.
- **Redis URL/auth error:** use the Render Key Value internal connection URL from the Render dashboard/Blueprint reference. Do not expose Key Value publicly.
- **Slow first request:** expected after Render Free sleeps. There is deliberately no keep-awake pinger.
- **429 from Gemini:** stop repeated testing and wait for the applicable free-tier quota window. Do not add billing.
- **Memory or storage pressure:** stop the public demo and inspect free-tier usage. Do not upgrade automatically.

## Scope and safety

This is a public portfolio demonstration, not a production service. Free instances can restart, Redis state is ephemeral, no load/capacity guarantee exists, and external model quotas can be exhausted. Only synthetic demo content is permitted. Never commit secrets, credentials, connection URLs, database exports, or real customer content.
